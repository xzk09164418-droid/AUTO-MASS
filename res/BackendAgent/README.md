# 后端启动代理

此程序只管理后端进程，与 Node 前端分开运行。关闭浏览器或 Node 不会结束代理或 Python；业务仍通过原 HTTP/WebSocket 接口访问。

启动过程：代理读取全局配置中完整有效的远程桌面启动提示，复用原有远程桌面宿主建立会话，在该会话中启动代理工作进程，再启动一次 Python 业务后端。完整配置的验证、迁移、调度与通知仍由 Python 负责；配置缺失或需要修正、宿主未编译时走原有 Python 启动路径。

跨会话启动使用原有宿主 `/launch` 能力。计划任务不能继承父进程标准流，因此会话间使用随机命名、仅当前用户可访问的管道；工作进程与 Python 之间重定向 stdio，无控制台窗口。管道使用逐行 JSON，包含协议版本、进程身份、原始输出和退出码，不承载业务接口，不新增监听端口。

后端会核对主代理 PID 和创建时间，代理丢失后按原有会话守卫正常收尾。代理等待 Python 输出排空和退出，只关闭自己创建的宿主，不触碰共享宿主；完整退出仍由托盘注销远程桌面。原有脚本程序包装器保留。

构建：`scripts/install_release.ps1 -NoLaunch` 或 `scripts/build-web-package.ps1` 使用系统 .NET Framework C# 编译器生成 `AutoMas.BackendAgent.exe`。前端宿主检测到该文件时启动代理，否则仍可启动 Python；没有 Electron 依赖。

本机验证：相同配置各三次新建子会话、不运行真实队列。原启动链与代理的中位数分别为：核心服务 6.79/6.18 秒、首次成功健康请求 8.09/6.35 秒、全部服务 8.49/7.90 秒、Node 资源 0.366/0.360 秒。各指标均从 Node 启动起计，不相加；仅三次样本，受缓存和系统负载影响，不代表通信延迟稳定降低。原始证据保存在本机忽略目录 `test/performance/`。

已验证标准流中文、Windows 参数转义与空参数、退出码透传、非标准配置回退、远程会话身份、正常退出与代理回收，以及仅退出前端后 Python PID 保持不变。浏览器连接和托管管理页面正常；前端隔离回归覆盖启动、历史、配置、队列与调度页面，没有运行真实游戏。

## Explorer 实验（2026-10-23）

仅在临时编译宿主的一次新建子会话中设置连接级 `SecuredSettings2.StartProgram` 和 `WorkDir`，以无界面探针替代默认 Shell；没有修改系统或用户 Winlogon Shell。属性写入后读回一致，连接成功（约 1.88 秒），但探针没有启动，该子会话仍运行 Explorer，因此这条路径在本机没有达到跳过 Explorer 的目标。

实验未进入正式宿主或代理代码，测试会话已注销、临时源码和二进制已删除。主桌面 Explorer 的 PID 在实验前后相同。保留正常桌面启动方式，不能据此宣称减少了 Explorer 的启动时间；后续若要更换桌面 Shell，需要独立兼容性验证。
